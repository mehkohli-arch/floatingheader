AI-Ready Design Systems

Rebuilding CMG's design systems so designers, engineers and AI tools can all build with them correctly. Dark mode for our loan software in under a month, and a complete customer-facing system in 4 months.

Why this matters

AI needs clear rules

More design work now happens with AI tools. AI is fast, but it only follows the rules it's given. If the same color is called "pink-3" in one place and "brand" in another, people get confused and AI makes mistakes.

So I set out to make our design systems AI-ready: every design decision stored as a named setting, and every rule written out in plain language that explains what to use, when and why. The clearer the system, the less room for confusion, whether a person or an AI is building.

  • Design tokens: named settings, like "page background" or "small spacing," defined once and used everywhere.
  • Storybook: a living library of the real coded components that anyone can browse and try.
  • PrimeNG: the ready-made code library our engineers build with.
Project 1 · Clear 2.0, our employee loan software

Dark mode in under a month

Clear 2.0 is the software CMG employees use every day to manage loans. The team wanted dark mode, but technical debt stood in the way: one-off pieces of code built outside the design system, each styled its own way.

Instead of patching screens one by one, I fixed the foundation.

  1. Add a semantic layer to the tokens

    I restructured our tokens and added a layer named by purpose, like "primary action" or "page background," instead of by color. Switching to dark mode now means changing what each purpose points to, not redesigning every screen.

  1. Follow PrimeNG more closely

    I aligned the token structure with PrimeNG, the code library engineers use, so design and code speak the same language.

  1. Work around the one-offs

    I planned around the older one-off code so dark mode could ship without waiting for a full rewrite.

  1. Put every component in Storybook

    I built a Storybook version of every component, with both React and Angular versions, so engineers on either technology use the same tested parts.

Project 2 · Our customer-facing design system

A full system in 4 months

Next, CMG needed a design system for the products its customers use. With AI built into my workflow, I delivered it in 4 months, about a year's worth of work.

I built it in Angular only, because that's what the engineers on these products use, and followed PrimeNG closely. It has three parts:

Figma

A ready-to-use component library

Designers start every screen with on-brand, accessible components instead of building from scratch.

Storybook

Prototyping with Claude

The real coded components, set up so Claude can prototype with them. Prototypes use the same parts engineers ship.

Rules

Guidance for Claude to follow

Written rules that tell Claude which components and tokens to use, when and why, so AI output meets our experience design standards.

The bigger idea

Empowering the whole company

With everything in Storybook, people across the company, not just designers, can explore, prototype and build on their own, while staying aligned with our experience design standards.

Design systems used to be documentation for designers and engineers. Now they're also instructions for AI. That makes complete tokens and clear, plain-language rules more important than ever.

What I learned

Clarity scales, for people and AI

  • Fix the foundation first. A semantic token layer turned dark mode from a redesign into a switch.
  • Write for two readers. Rules clear enough for a new designer are clear enough for an AI tool.
  • Meet engineers where they are. Matching PrimeNG and their technology makes the system easy to adopt.
