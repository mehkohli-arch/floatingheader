    Systems thinking

    To me, a design system is a product whose users are designers and engineers. I build systems grounded in code, accessible from the start, and simple enough that teams want to adopt them.

    01

    Audit before you abstract

    I start from the real components in production, reviewed with engineers, so the system fixes the drift teams actually have.

    02

    Tiered token architecture

    Primitive → semantic → component tokens turn theming, dark mode, density and multi-brand into a change of values, not a rebuild.

    03

    Accessible by default

    Contrast, focus states, ARIA roles, keyboard and screen-reader support are built into every component, so every product inherits them.

    04

    Aligned with the code library

    Figma components mirror the engineering framework (for example PrimeNG), with developer-ready specs, so handoff needs no translation.

    05

    Adoption through people

    Docs, design critiques, design–engineering syncs and mentorship, so any designer can contribute without a long ramp-up.
