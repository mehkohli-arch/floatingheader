02 — Design systems practice

Systems that teams actually adopt.

A design system is a product with designers and engineers as its users. I build systems that are grounded in code, accessible from the start, and governed so they stay healthy as products grow.

01

Audit before you abstract

I start from real component usage in production with engineers, not an idealized library, so the system solves the drift teams already have.

02

Token architecture

Primitive → semantic → component tiers make theming, dark mode, density and multi-brand a change of values, not a rebuild.

03

Accessibility by default

WCAG contrast, focus states, ARIA roles, keyboard and screen-reader support are built into each component, so every product inherits them.

04

Aligned with the code library

Components mirror the engineering framework (for example PrimeNG) and include developer-ready specs, so handoff needs no translation.

05

Docs, critique and mentorship

Usage guidelines, design-engineering syncs and hands-on coaching turn the library into shared practice, so any designer can contribute without a long ramp-up.
